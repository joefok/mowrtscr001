Database REST connection

Authentication: No client authentication

  • No Firebase SDK or Firebase login.
  • No auth query parameter.
  • No Authorization header.
  • No cookies sent with database requests.

The server must support GET, PUT, PATCH and DELETE on .json paths, including multi-location PATCH updates and null deletion. CORS must allow this website's origin and these HTTP methods. Polling is used instead of Firebase WebSockets.

A local browser ID is not authentication. If the server allows public database access, classroom records and invitation keys are not protected. Teacher/assistant controls in this page are not a security boundary.

TURN configuration

TURN credentials are still required for the media relay. “No client authentication” here refers to database requests. TLS 443 requires a real TURN TLS listener and trusted certificate; this hostname field does not configure the server.

   Room URL settings apply through the controlling teacher.
   start=1 prepares the sharing button but never bypasses a real click
   or browser capture permission.
  

  

   Up to four active staff viewers receive separate student streams.
   Additional viewers multiply upload and TURN traffic.
   This is a polling-based prototype, not a capacity-tested 40-device deployment.
   For larger installations, consider server subscriptions and an SFU.
  

  

   Do not open the same student identity in multiple active tabs.
   Use a separate browser profile or device to test a student while
   acting as teacher.
