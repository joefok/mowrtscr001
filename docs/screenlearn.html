TURN Classroom Monitor — v3

Single-file prototype with manual pairing. Screen video and live configuration use TURN-relayed WebRTC. The creating teacher coordinates the classroom and forwards screens to additional teachers. Keep that browser open. Screen capture requires permission and a supported desktop browser.
TURN not configured

No TURN IP address is embedded. Enter an IPv4 address or hostname when prompted. It is stored in this browser's cookie, not hidden from its user. Port: 3489. Static test credentials are public in the source.

Create or join

A joining participant's invitation determines their role. Selecting Teacher does not grant access to another classroom. Each created lesson receives a unique session ID.

Pair browsers

Coordinator: create an invitation and send it privately. Recipient: paste invitation, click Join, and send the generated answer back. Coordinator: paste that answer and accept it. Create a separate invitation for every participant.

Exchange pairing text privately. It contains connection information and acts as admission material. There is no account-authentication backend.

Shared classroom settings

Maximum 64 positions. Occupied seats cannot be removed or disabled. Incoming updates preserve unsent settings drafts. All admitted teachers can edit; the coordinator serializes changes.

Tap a tile to enlarge. Enlargement does not recover detail missing from a tiny preview. Students receive classroom seat metadata but not other students' screen video. Health is measured independently by each viewer.

Diagnostics, limitations, and review notes 

  
    
    
  • No automatic discovery, account login, or coordinator failover.
    • 
    
  • coturn is a relay, not a signaling server, database, or SFU.
    • 
    
  • Additional teachers increase coordinator upload and processing.
    • 
    
  • Layout defaults persist locally by classroom name.
    • 
    
  • Background throttling and device sleep may interrupt updates.
    • 
    
  • Grey means unavailable or uncertain, not proof of misconduct.
    • 
    
  • Static desktops can remain healthy if encoded frames continue arriving.
    • 
    
  • Bitrate settings are targets, not guaranteed total bandwidth.
    • 
    
  • Long sessions can accumulate stopped SDP sections.
    • 
    
  • Production needs authenticated signaling, temporary TURN credentials,
      persistent authority, and usually an SFU for multiple viewers.
