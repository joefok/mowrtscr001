Classroom Screen Monitor

Teacher creates a room. Students open its link and click an empty seat. Screen sharing always requires browser permission. Keep the creating teacher's browser open.
Not connected to signaling

Firebase provides room discovery and initial signaling. Screen video and WebRTC DataChannels are forced through TURN. No TURN host is embedded in this file.

Teachers create rooms. Students open an existing room ID or use the teacher's shared room link.

Not in a room

Configure the services, then create or open a room.

Up to 64 grid positions. Occupied seats cannot be removed by shrinking the grid. Tiny previews are for general activity, not readable text.

Join requests and connected students

Click an empty tile to request that seat and share your screen. If auto accept is off, wait for the teacher.

Diagnostics and important limitations 

  
    
    
  • One controlling teacher per room; multiple rooms can run simultaneously.
    • 
    
  • Anonymous Firebase authentication is not school-account identity verification.
    • 
    
  • Anyone with a room link may request access. Use manual acceptance when needed.
    • 
    
  • The creating teacher must remain online. No coordinator failover is included.
    • 
    
  • Student names and assigned seats are visible to room participants.
    • 
    
  • Static screens may continue producing frames and remain healthy.
    • 
    
  • Grey means unavailable or uncertain, not proof of misconduct.
    • 
    
  • Production should use authenticated school accounts, temporary TURN
      credentials, abuse protection, and room-data cleanup.
    •
